# Studio animé — version web 3.4.4

`index.html` contient VideoStory 3.4.4 et charge `pastel-theme.css` : interface pastel tactile sur tous les écrans, accueil mobile avec mascotte 3D, cartes de projets assorties et icône PWA coordonnée. Les illustrations transparentes sont optimisées en WebP. Le mix audio est normalisé; chaque narration est vérifiée avant planification. Speechify est demandé en PCM brut signé 16 bits à 24 kHz; le client convertit directement les échantillons en `AudioBuffer` sans décodeur de conteneur du navigateur. Si une réponse HTTP réussie ne contient pas d’audio, l’application essaie une seule fois le WAV et accepte plusieurs enveloppes; si l’audio manque encore, elle affiche le motif/identifiant Speechify pour faciliter le diagnostic. L’export reste bloqué si une voix manque ou est silencieuse. Le domaine canonique de production est `https://videos-plus.vercel.app/`; `https://elka-jobnet.vercel.app/` reste actif comme alias.

La version 3.4.3 conserve la détection des dialogues et les voix Speechify distinctes par personnage, ainsi que les associations de voix par profil et par langue. Elle harmonise aussi la lumière des personnages avec le décor, retire le halo clair des personnages détourés, ajoute un rebond/écrasement plus naturel pendant la marche et un pivot plus souple des invités. Ces effets s’appuient sur des calques Canvas et conservent les assets intégrés; l’éclairage se replie sur le rendu normal si son calque auxiliaire ne peut pas être créé. Elle corrige aussi le retour du rendu serveur : Video Plus autorise uniquement les callbacks HTTPS des hôtes Modal et Render prévus, sur la route de résultat `/render/render_<id>/result`, afin que les deux moteurs puissent transmettre leur MP4 sans accepter des domaines arbitraires. La version 3.4.3 ajoute des plans photo cinématiques et des sprites 3D pré-rendus (25 images WebP embarquées); ils ne s’activent que sur des scènes compatibles et laissent le moteur de personnage habituel gérer les apparences personnalisées, les protagonistes féminins, les costumes du récit et les préférences de mouvement réduit.

La version 3.4.4 évite de fusionner des phrases qui déplacent l’action vers un autre lieu ou un autre type de véhicule. Sur les scènes compatibles, le rendu 3D ajoute des poses assise, de présentation et de pointage, ainsi que six formes de bouche synchronisées à la voix. Les scènes incompatibles, les apparences personnalisées et les préférences de mouvement réduit conservent le rendu Canvas existant.
## Sous-titres automatiques

Les sous-titres sont incrustés dans les vidéos exportées. Depuis l’éditeur, le bouton **CC** télécharge aussi un fichier `.srt` UTF‑8 autonome, découpé comme les sous-titres affichés et synchronisé avec les repères de parole Speechify lorsqu’ils sont disponibles (sinon, le minutage estimé des mots est utilisé). Le fichier porte le même nom de base que la vidéo et peut être importé séparément sur les plateformes qui acceptent les pistes de sous-titres.

## Déploiement et Speechify

Les changements poussés sur `main` sont déployés automatiquement par Vercel. La narration utilise `/api/speechify`; la clé est conservée uniquement côté serveur dans `SPEECHIFY_API_KEY`. Dans **Vercel → projet → Settings → Environment Variables**, vérifie que cette variable est configurée pour Production (et Preview si nécessaire), puis relance un déploiement après toute modification. Ne mets jamais la clé dans le HTML, le navigateur ou GitHub.

Dans l’app, ouvre **Paramètres → Tester la voix Speechify** pour valider la synthèse. `simba-3.0` est utilisé par défaut pour le français; `simba-3.2` est réservé à l’anglais. La route serverless limite le texte à 2 000 caractères et efface les anciennes clés locales pendant la migration.

Par défaut, chaque projet choisit une voix d’après le profil féminin, masculin ou neutre/narrateur de son personnage principal. Dans **Paramètres → Associations automatiques**, choisis la langue (français, anglais ou espagnol), puis charge le catalogue Speechify pour sélectionner séparément la voix de chaque profil. Les associations restent sauvegardées par langue et sont utilisées dans l’aperçu comme à l’export; les réglages initiaux sont Adeline/Alexandre (et Alexandre pour le neutre), Alicia/Alec (Alec pour le neutre) et Aitana/Alejandro (Alejandro pour le neutre). Pour imposer une seule voix à toutes les vidéos, désactive **Voix automatique selon le personnage principal** et utilise le réglage manuel.

## Rendu serveur Modal CPU

Le rendu mobile de 18 à 180 secondes utilise le worker Modal `videos-plus-renderer`. Il fonctionne sans GPU, avec 2 vCPU et 4 Gio de mémoire, un seul conteneur au maximum, et une réduction à zéro après 60 secondes d’inactivité. La formule Starter du workspace observée au déploiement affichait 1 $ de crédit gratuit disponible; aucun moyen de paiement n’a été ajouté. Modal peut refuser les nouvelles tâches lorsque le crédit gratuit est épuisé. Les rendus plus courts ou hors mobile restent locaux. Render est conservé comme solution de retour arrière; ne le supprimer qu’après validation d’exports réels sur Modal.

Pour redéployer le worker depuis ce dépôt, installe le CLI Modal puis exécute `modal deploy modal-worker/modal_app.py` après authentification. L’image utilise Node 22, Chromium et FFmpeg; Playwright exige Node 20 ou plus. Le worker reste CPU-only : l’ajout d’un GPU n’accélérerait pas son encodage FFmpeg actuel.

Les exports sonores de **2 minutes ou plus** utilisent par prudence le chemin d’enregistrement compatible plutôt que le muxage AAC WebCodecs. Le format final (MP4/WebM) dépend des capacités du navigateur. Pour un export long, garde l’application au premier plan jusqu’à la fin. Si une vidéo contient une narration, l’application ne valide plus un fichier tant que toutes les scènes n’ont pas une piste vocale préparée.

L’export haute qualité peut être plus lent et consommer davantage de mémoire sur téléphone. Le chemin de secours teste le coût du rendu, essaie le 720p puis peut passer en 540p si nécessaire pour éviter une vidéo saccadée; un message l’indique et la préférence enregistrée ne change pas. Sélectionne aussi **Paramètres → Qualité de l’export vidéo → 720p** si l’appareil chauffe, manque de mémoire ou interrompt l’export.

## Domaine public et visibilité Google

Le projet Vercel s’appelle déjà `videos-plus`. L’adresse canonique voulue est `https://videos-plus.vercel.app/`; `https://elka-jobnet.vercel.app/` est conservée comme alias pour ne pas casser les anciens liens. Le domaine doit être affecté à l’environnement Production dans **Settings → Domains**. Les URL canonical, Open Graph et JSON-LD de `index.html`, ainsi que `robots.txt` et `sitemap.xml`, doivent toujours correspondre au domaine principal.

Après déploiement, Google doit réexplorer le site et le sitemap : le remplacement de l’adresse affichée dans ses résultats peut prendre du temps et n’est pas instantané. Documentation officielle : [gérer les domaines Vercel](https://vercel.com/docs/domains/working-with-domains).
